# Copilot Instructions for tidytracks

## Repository Overview

`tidytracks` is an R package that provides tidy functions to analyze
tracking data, based on move2 objects. The package follows modern R
package development practices and integrates with the tidyverse
ecosystem.

## Package Structure

- **R/**: Source code for exported functions
- **tests/testthat/**: Test files using testthat framework
- **man/**: Auto-generated documentation (DO NOT EDIT manually)
- **data/**: Package data
- **data-raw/**: Scripts to generate package data
- **vignettes/**: Package vignettes and long-form documentation
- **inst/**: Additional files to be installed with the package

## Key Dependencies

- **move2**: Core dependency for movement data structures
- **sf**: Spatial features for geographic data
- **units**: Handle physical units correctly
- **dplyr, tidyr, purrr**: Tidyverse tools for data manipulation
- **testthat**: Testing framework (\>= 3.0.0)

## Coding Conventions

### General R Style

- Use snake_case for function and variable names
- Follow standard R package conventions
- Use roxygen2 for documentation with markdown formatting enabled
- Keep functions focused and single-purpose
- Use meaningful parameter names

### Documentation Standards

- All exported functions MUST have roxygen2 documentation with:
  - `@param` for each parameter with clear descriptions
  - `@return` or `@returns` describing the return value
  - `@export` for exported functions
  - `@keywords internal` for internal functions
  - Brief description of what the function does
- Use complete sentences in documentation
- Include examples where appropriate
- Document units for physical quantities (e.g., speed, distance)

### Code Quality

- Linting is configured in `.lintr` using `lintr` package
- Linter excludes `return_linter` by default
- Some ggplot2 wrapper functions have `object_name_linter` disabled to
  match ggplot2 conventions
- Run `lintr::lint_package()` before committing changes

### Error Handling

- Use [`stop()`](https://rdrr.io/r/base/stop.html) for errors with
  informative messages
- Use [`warning()`](https://rdrr.io/r/base/warning.html) for warnings
- Check input types explicitly (e.g., `if (!inherits(x, "move2"))`)
- Provide helpful error messages that guide users

### Function Wrappers

- Many functions are thin wrappers around move2 functions (e.g.,
  `event_speed <- move2::mt_speed`)
- These wrappers provide consistent naming and additional documentation
- When creating wrappers, maintain full roxygen2 documentation

## Building and Testing

### Building the Package

``` r

# Build and check the package
devtools::check()

# Build documentation
devtools::document()

# Install locally
devtools::install()
```

### Running Tests

``` r

# Run all tests
devtools::test()

# Run specific test file
testthat::test_file("tests/testthat/test_event_flag_mcconnell.R")
```

### Testing Conventions

- Use testthat (\>= 3.0.0) with edition 3
- Test files are named `test_*.R` in `tests/testthat/`
- Use descriptive test names with `test_that()`
- Include tests for:
  - Correct outputs with valid inputs
  - Error handling with invalid inputs
  - Edge cases and boundary conditions
  - Unit conversions where applicable
- Use `expect_true()`, `expect_equal()`, `expect_error()`, etc.
- Test data is stored in `tests/testthat/testdata/`

### CI/CD

- GitHub Actions runs R-CMD-check on multiple OS (macOS, Windows,
  Ubuntu) and R versions (devel, release, oldrel-1)
- Test coverage is tracked with Codecov
- All PRs must pass R CMD check

## Spatial Data Handling

- The package works with both projected and unprojected (lon/lat)
  coordinates
- Check coordinate system with
  [`sf::st_is_longlat()`](https://r-spatial.github.io/sf/reference/st_is_longlat.html)
- Use geodesic distance for lon/lat, Euclidean for projected
- Handle units correctly using the `units` package
- Convert between unit systems as needed with
  [`units::ud_convert()`](https://r-quantities.github.io/units/reference/udunits2.html)

## Common Patterns

### Working with move2 Objects

``` r

# Extract coordinates
coords <- sf::st_coordinates(x)

# Extract time
time <- event_time(x)

# Extract track IDs
id <- event_track_id(x)

# Check if move2 object
if (!inherits(x, "move2")) {
  stop("x must be a move2 object")
}
```

### Units Handling

``` r

# Check if units object
if (!inherits(max_speed, "units")) {
  stop("max_speed must be a units object: e.g. units::as_units(50, 'm/s')")
}

# Convert units (example with defined target units)
target_units <- "m/s"
max_speed <- units::ud_convert(unclass(max_speed), units(max_speed), target_units)
```
